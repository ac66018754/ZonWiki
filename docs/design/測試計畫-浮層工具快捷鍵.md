# 測試計畫：筆記右下角浮層工具快捷鍵（含開問啦畫布）

日期：2026-08-10
分支：feat/overlay-toolbar-shortcuts（自 origin/main 切出）

## 一、需求摘要（使用者裁示）

1. 右下角工具列（DrawingToolbar，筆記閱覽頁與開問啦畫布共用）的功能加「無修飾鍵單鍵」快捷鍵。
2. 生效範圍：**筆記閱覽頁（預覽分頁）與開問啦畫布**。首頁、行程（Todo）、筆記編輯頁（含編輯模式）一律不生效。
3. 鍵位配置：
   - 工具依工具列順序用數字鍵：`1` 畫筆、`2` 螢光筆、`3` 直線、`4` 矩形、`5` 橢圓、`6` T 文字框、`7` 局部橡皮擦、`8` 整體橡皮擦、`9` 框選橡皮擦。
   - 英文單字首字母：`c` 目錄（contents，僅筆記頁）、`s` 便利貼（sticky）、`i` 圖片板（image）。
4. 不做快捷鍵：結束繪圖（已有滑鼠右鍵）、清除全部（破壞性、防誤觸）、儲存浮層快照（低頻）。
5. 工具列收合（或畫布工具箱整個關閉）時按快捷鍵：**不展開工具列，但工具照樣啟用**。
6. 按鈕 icon 旁顯示鍵帽提示，例如 `T(6)`；提示須跟隨使用者改鍵即時更新。
7. 沿用既有 `shortcuts.ts` ＋ `ShortcutRuntime` 系統：可改鍵、衝突偵測、跨裝置同步（User.ShortcutsJson）、`/profile/shortcuts` 設定頁自動列出。

## 二、設計要點（實作前定案）

- 新增 scope `overlay`（顯示名「浮層工具（筆記閱覽／畫布）」）：9 個工具＋便利貼＋圖片板。
- `toggleToc`（`c` 目錄）放既有 `notes` scope——畫布沒有目錄，語意上屬筆記頁。
- `PAGE_CONTEXTS` 更新為三個情境：`[global, tasks]`、`[global, notes, overlay]`（筆記頁）、`[global, overlay]`（畫布）。
- `ShortcutRuntime`：`overlay` 動作在路徑 `/notes*` 或 `/canvas*` 時 `preventDefault` 並派發 `SHORTCUT_ACTION_EVENT`；其餘頁面不派發。
- 監聽者（誰執行動作）：
  - `NoteOverlay`（僅在筆記閱覽頁預覽分頁掛載；編輯模式整個卸載）→ 工具切換、加便利貼/圖片板/文字框、`toggleToc`（經既有 `onToggleToc` prop）。
  - `CanvasAnnotationLayer`（畫布）→ 工具切換、加便利貼/圖片板/文字框；忽略 `toggleToc`。
- 「不展開也能啟用」對 selectTool 類天然成立（工具狀態在父層，收合只是 UI 狀態；畫布 `toolbarOpen=false` 時擷取面仍照 `drawingActive` 渲染）。**例外（審查抓到）**：畫布端 `addTextBox` 既有副作用會 `setToolbarOpen(true)`（CanvasAnnotationLayer.tsx:319）——鍵盤觸發路徑必須跳過展開（改成參數化：按鈕觸發照舊展開、鍵盤觸發不展開），否則違反裁示 #5。
- 鍵帽提示：新增共用 hook（讀取生效鍵、訂閱 `SHORTCUTS_UPDATED_EVENT`），由父層算好傳入 DrawingToolbar 的新 prop（保持該元件純呈現）。
- 設定頁 `/profile/shortcuts` 的 scopes 陣列目前寫死 `["global","tasks"]`（既有缺口：notes 的 `a` 沒列出）→ 補上 `notes` 與 `overlay`。

## 五、風險與邊界

- 數字鍵在既有頁面無人使用（已盤點：全域 h/t/q/n/f/v、tasks y/m/w/d/a、notes a、Delete/Ctrl+Z/Esc）。
- 瀏覽器預設：無修飾單鍵在主內容區無預設行為；系統本就跳過 Ctrl/Cmd/Alt 與輸入元素。
- `/notes` 清單頁、問題頁等會收到派發但無監聽者 → 無操作（可接受；數字鍵無瀏覽器預設行為，preventDefault 無副作用）。
- 編輯彈窗（edit-popout）開啟時：主視窗渲染的是「即時預覽」分支，**NoteOverlay 整個卸載**（page.tsx:1486-1497）→ 快捷鍵無效果，與編輯模式同理（審查更正：並非「閱覽態照常生效」）。
- 改鍵存後端；設定頁擷取模式已用 capture＋stopImmediatePropagation，不會誤觸新動作。
- Shift 修飾鍵不在排除清單（既有行為）：`Shift+S`／Caps Lock 大寫仍觸發（toLowerCase 正規化），以 B5b 留底。
- React Flow 鍵盤行為已查證：/canvas 目錄無自訂 deleteKeyCode/selectionKeyCode/zoomActivationKeyCode/panActivationKeyCode，沿用預設（Backspace/Delete、Shift、Ctrl/Meta、Space），與 1-9/c/s/i 無衝突；升版 @xyflow/react 時需回查此假設。
- StrictMode（Next 預設開）雙掛載：新監聽器 useEffect 必須對稱 add/remove；非幂等動作（addSticky/addSlide/addTextBox 會打 API）以 E2/E2b「恰好一個」驗證。
